CME-202

Host-Based Firewall (firewalld/nftables)

Isolate Network Unquantified evidence Preventive

Description

Per-host network access control using firewalld zones or nftables rules. Restricts which network sources can reach specific services, reducing attack surface.

CVSS Vector Impacts

Metric Transition Rationale
Attack Vector (AV) N → A Service only reachable from adjacent/authorized networks
Scope (S) C → U Firewall prevents lateral movement to other services

Remediation

firewalld zone-based service restriction rhel

Precondition: command -v firewall-cmd >/dev/null 2>&1

  1. Enable and start firewalld if not already running

    $ systemctl enable --now firewalld
    Reversible
    Undo command
    $ systemctl disable --now firewalld

  2. Set the default zone to drop (deny all inbound by default, only explicitly allowed services/ports are reachable)

    $ firewall-cmd --set-default-zone=drop
    Reversible
    Undo command
    $ firewall-cmd --set-default-zone=public

  3. Allow SSH from a specific management network only (replace <mgmt_cidr> with your admin network, e.g., 10.0.1.0/24)

    $ firewall-cmd --permanent --zone=drop --add-rich-rule='rule family=ipv4 source address=<mgmt_cidr> service name=ssh accept'
    Reversible
    Undo command
    $ firewall-cmd --permanent --zone=drop --remove-rich-rule='rule family=ipv4 source address=<mgmt_cidr> service name=ssh accept'

  4. Allow a specific application service port from authorized client networks only (replace <service_port> and <client_cidr>)

    $ firewall-cmd --permanent --zone=drop --add-rich-rule='rule family=ipv4 source address=<client_cidr> port port=<service_port> protocol=tcp accept'
    Reversible
    Undo command
    $ firewall-cmd --permanent --zone=drop --remove-rich-rule='rule family=ipv4 source address=<client_cidr> port port=<service_port> protocol=tcp accept'

  5. Reload firewalld to apply permanent rules

    $ firewall-cmd --reload
    Not reversible
Verify:
$ firewall-cmd --state && firewall-cmd --get-default-zone && firewall-cmd --list-all

nftables default-deny ruleset with per-service allowlisting linux

Precondition: command -v nft >/dev/null 2>&1

  1. Create a default-deny nftables ruleset file that allows established connections, ICMP, loopback, SSH from a management network, and a specific service port from authorized clients (replace <mgmt_cidr>, <client_cidr>, <service_port>)

    $ printf '#!/usr/sbin/nft -f\nflush ruleset\ntable inet filter {\n chain input {\n type filter hook input priority 0; policy drop;\n ct state established,related accept\n ct state invalid drop\n iif lo accept\n ip protocol icmp accept\n ip6 nexthdr icmpv6 accept\n ip saddr <mgmt_cidr> tcp dport 22 accept\n ip saddr <client_cidr> tcp dport <service_port> accept\n }\n chain forward {\n type filter hook forward priority 0; policy drop;\n }\n chain output {\n type filter hook output priority 0; policy accept;\n }\n}\n' > /etc/nftables/cme-202.nft
    Reversible
    Undo command
    $ rm -f /etc/nftables/cme-202.nft

  2. Include the CME-202 ruleset from the main nftables config if not already included

    $ grep -q 'cme-202.nft' /etc/sysconfig/nftables.conf 2>/dev/null || echo 'include "/etc/nftables/cme-202.nft"' >> /etc/sysconfig/nftables.conf
    Reversible
    Undo command
    $ sed -i '/cme-202.nft/d' /etc/sysconfig/nftables.conf

  3. Load the ruleset into the running kernel

    $ nft -f /etc/nftables/cme-202.nft
    Reversible
    Undo command
    $ nft flush ruleset

  4. Enable the nftables service so rules persist across reboots

    $ systemctl enable nftables
    Reversible
    Undo command
    $ systemctl disable nftables
Verify:
$ nft list ruleset | grep -c 'policy drop'
