CME-801

Multi-Factor Authentication (MFA)

Harden Identity Unquantified evidence Preventive

Description

Enforce multi-factor authentication (MFA) requiring two or more independent authentication factors before granting access. Supported second factors include time-based one-time passwords (TOTP via authenticator apps), FIDO2/WebAuthn hardware security keys, smart cards (PIV/CAC via PKCS#11), and push-based approval. MFA ensures that a compromised password alone is insufficient for account access — the attacker must also obtain or bypass the second factor through a separate channel (physical theft, real-time phishing proxy, SIM swap), each of which adds substantial complexity. FIDO2 keys provide the strongest protection as they are bound to the origin and resistant to phishing. TOTP is vulnerable to real-time proxy phishing (e.g., EvilGinx2) but still requires significantly more attack infrastructure than password-only attacks. MFA is enforced at the authentication layer via PAM modules (Linux), conditional access policies (Azure AD/Entra ID), or IdP configuration (Keycloak, Okta, FreeIPA).

Verification

Verify MFA enforcement via PAM modules, SSSD/FreeIPA OTP, smart card, or IdP conditional access policy

$ grep -rE 'pam_google_authenticator|pam_oath|pam_u2f|pam_duo' /etc/pam.d/ 2>/dev/null | grep -c 'auth.*required'
# Expected: >=1
Platform: linux
$ grep -c 'pam_sss' /etc/pam.d/system-auth 2>/dev/null && ipa user-show admin --all 2>/dev/null | grep -i 'authentication types' | grep -ic 'otp'
# Expected: >=1
Platform: rhel
$ grep -rE 'pam_pkcs11|pam_p11' /etc/pam.d/ 2>/dev/null | grep -c 'auth'
# Expected: >=1
Platform: linux
$ Get-MgIdentityConditionalAccessPolicy | Where-Object {$_.GrantControls.BuiltInControls -contains 'mfa' -and $_.State -eq 'enabled'} | Measure-Object | Select-Object -ExpandProperty Count
# Expected: >=1
Platform: windows
